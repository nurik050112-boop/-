# 🤖 Промпты для Codex

Codex меняет **настоящий код** в твоём проекте. Чтобы он делал это правильно — дай ему контекст
один раз, а потом проси фичи по шаблонам. Всё в `[квадратных скобках]` — заменяй на своё.

---

> 💡 В проекте есть файл **AGENTS.md** — Codex читает его сам и уже знает стек, правила и команды.
> Контекст-промпт ниже — короткое напоминание на случай, если ассистент его не подхватил.

## 0️⃣ Контекст-промпт (вставь ПЕРВЫМ, один раз в начале проекта)

```
Это мой проект на стеке: Vite + React + TypeScript + Supabase + Vercel.
Следуй правилам из AGENTS.md. Коротко:
- Supabase уже подключён в src/lib/supabase.ts (ключи в .env). Используй ЕГО.
- Базу меняй ТОЛЬКО миграциями: npm run db:new -- имя → впиши SQL → сам сделай dry-run,
  проверь RLS → сам примени db:push и проверь результат.
  Никакого ручного SQL Editor. На каждую таблицу — RLS «только свои строки».
- Код на TypeScript, без any. Маленькие компоненты. Перед концом — npm run build.
- App.tsx хранит только маршруты. Каждый большой экран делай в src/pages/ со своим URL:
  /game, /quiz, /profile и т.д. Не складывай весь продукт на главную страницу.
- Не печатай ключи и не коммить .env.
- Объясняй кратко, что поменял и в каких файлах.
Подтверди, что понял, и жди мою первую задачу.
```

---

## 🔁 Главное правило цикла

После КАЖДОГО промпта Codex: **посмотри что изменилось → запусти `npm run dev` → работает? →
`git push`**. Сломалось — попроси починить, не коммить сломанное.

## 🗓️ Промпты по дням (шаблоны)

### День 2 — подключение Supabase: РУКАМИ, не через Codex

> ⚠️ Эти команды интерактивные (браузер, пароль) — Codex с ними путается. Вводи их **сам**,
> по одной, в терминале VSCode. Полная пошаговая инструкция — в `README.md`, шаг 6.

```bash
npm run db:login                       # вход (подтверди в браузере)
npm run db:link -- --project-ref REF   # REF — из адреса https://REF.supabase.co
npm run db:push -- --dry-run           # посмотреть, что применится
npm run db:push -- --yes               # создать таблицы
```

Пароль базы вводи прямо в терминал (символы не видны — это нормально). В терминал вставляй
только строки из блоков кода — обычный текст он понимает как команды.

### День 3 — твоя идея + база + профиль
Промпт 1 — переделай под идею:
```
Переделай стартовый экран под мою идею: [опиши идею в 1-2 предложениях].
Главную оставь короткой, а основную функцию сделай отдельной страницей с понятным маршрутом
[например: /game, /quiz или /habits]. App.tsx должен содержать только маршруты.
Создай новую миграцию (npm run db:new -- имя) под нужные поля, проверь её через
db:push --dry-run, сам примени db:push --yes и проверь результат. Если нужен вход или
пароль — попроси только подтвердить браузер или ввести пароль прямо в терминал.
```
Промпт 2 — память + профиль:
```
Сделай так, чтобы [мои данные: счёт игры / прогресс / список] сохранялись в Supabase и
подгружались при входе. Добавь страницу профиля: email, аватар (буква имени) и статистику —
[например: сколько [записей] создано, дата регистрации]. Для новых таблиц создавай миграции
(npm run db:new), включай RLS «только свои строки», сам делай dry-run, применяй db:push и
проверяй результат.
```

### День 4 — дизайн + UX
Для приложения:
```
Улучши дизайн и UX приложения. UI: фон [#код], тёмный текст, ОДИН акцентный цвет [#код],
шрифт Inter, воздух и выравнивание, единый стиль на всех экранах.
UX: с первого экрана понятно, что это и куда нажать; главное действие — не дальше 2-3 кликов;
убери всё, что запутывает.
Добавь крючок возвращения: [streak по дням / XP и уровни / таблица лидеров / ежедневный челлендж].
```
Для игры:
```
Улучши UX моей игры, игровую механику не трогай. Сделай: экран старта с названием и кнопкой
«Играть», понятное управление с подсказкой, мгновенный отклик на действия (анимация/эффект),
крупный читаемый счёт, экран проигрыша с результатом и кнопкой «Ещё раз».
Меню и кнопки — в едином аккуратном стиле.
Добавь крючок возвращения: [лучший счёт / streak / таблица лидеров / ежедневный челлендж].
```

### День 5 — настоящий AI внутри продукта (Gemini)
```
Добавь AI-функцию: [что должен делать AI — например: генерировать 5 вопросов по теме /
давать совет по моим данным / отвечать в роли персонажа].
Используй уже готовую Edge Function 'ai' (Gemini) — вызывай её через
supabase.functions.invoke('ai', { body: { prompt, system } }) и показывай data.text.
Не создавай новую функцию и не вызывай модель с фронта напрямую.
System prompt (поле system): роль — [роль], тон — [тон], запреты — [чего нельзя], формат — [формат].
```
> Перед этим (один раз): добавь `GEMINI_API_KEY` в `.env` →
> `npm run ai:secret` → `npm run ai:deploy`.

### День 6 — реальные пользователи + онбординг
```
Добавь онбординг: welcome-экран в одно предложение «что это», подсказку на главной кнопке и
```

## 😴 Keep-alive — тоже РУКАМИ, одна команда (после db:push)

> Не через Codex. Выполни сам в терминале, когда `.env` заполнен и таблица `entries` создана:

```bash
npm run keep-awake:setup
```

Успех — строка `Keep-alive verified: https://github.com/.../actions/runs/...`.

Если ошибка про `gh` — один раз войди в GitHub и повтори команду:

```bash
gh auth login
```
Выбери: **GitHub.com** → **HTTPS** → **Login with a web browser**.
